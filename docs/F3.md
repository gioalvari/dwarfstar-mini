# F3 - Metal decode backend

F3 adds an Apple Metal decode backend selected with `--backend metal`; Metal is
the default when a system Metal device is available. `--backend cpu` retains the
F2 scalar reference path.

## Design

- `src/metal.m` compiles `metal/dsm.metal` at runtime with
  `newLibraryWithSource` and creates all compute pipelines once.
- GGUF remains mmap-backed. The backend wraps page-aligned tensor-data views with
  `newBufferWithBytesNoCopy`; large files are split at the device's
  `maxBufferLength`, so tensors receive a buffer plus an inner offset instead of
  copied weights.
- One command buffer encodes an entire token: Q8_0/F32 GEMVs, RMSNorm, Q/K
  RMSNorm, NEOX RoPE, FP32 KV writes, causal GQA attention, output projection,
  SwiGLU, residuals, final norm, and logits.
- Kernel dispatch is selected from the GGUF weight type. F4 can add Q2_K/Q3_K/
  Q4_K GEMV implementations to that dispatch without changing graph sequencing.

## Commands

```sh
make
./dsm -m models/Qwen3-1.7B-Q8_0.gguf -p 'The capital of France is' -n 16
./dsm -m models/Qwen3-1.7B-Q8_0.gguf --backend cpu -p Hi -n 1
tools/compare_backends.sh
```

The initial `Hi` first-step logits comparison measured a maximum absolute
CPU/Metal difference of `0.0128517`; both top-1 IDs were `25`. The remaining
small difference is expected from GPU reduction and transcendental ordering.
Each run prints distinct prefill and decode throughput measurements to stderr.

## Limitations

This is a correctness-first implementation. GEMV uses one group per output row;
attention recomputes its scalar softmax per output lane to avoid a cross-group
dependency. KV is FP32, there is no batch/prefill GEMM, no command-buffer
pipelining, and F4 quantization/MoE kernels are not implemented yet.
