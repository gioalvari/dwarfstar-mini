# F4 - K-quant decode

F4 adds CPU and Metal decode GEMV support for GGML `Q2_K`, `Q3_K`, `Q4_K`,
`Q5_K`, and `Q6_K`. Quantized token embeddings are dequantized on the host
before their first GPU use; all projection GEMVs dispatch their own weight type.

## Layouts

All K quants are 256-element super-blocks. `Q2_K` is 84 bytes: 16 packed
scale/min nibbles, 64 two-bit values, then FP16 `d` and `dmin`. `Q3_K` is 110
bytes: 32 high-mask bytes, 64 two-bit values, 12 packed six-bit scales, FP16
`d`. `Q4_K` and `Q5_K` use their GGML packed `get_scale_min_k4` scales/mins;
they are 144 and 176 bytes. `Q6_K` is 210 bytes: 128 low nibbles, 64 high-bit
bytes, 16 signed scales, and FP16 `d`.

`make check-quants MODEL` is replaced by `make check-quants` followed by
`./check-quants MODEL`; it compares the first two rows of every supported
tensor with llama.cpp `ggml_get_type_traits(type)->to_float`. `make
check-metal-gemv` builds a separate CPU-vs-Metal GEMV harness.

## Correctness

| Model | Quant types | CPU dequant vs GGML | Metal greedy vs llama-simple |
| --- | --- | --- | --- |
| Qwen3-1.7B Q8_0 | Q8_0 | existing | France 16, Fibonacci 32: exact |
| Qwen3-1.7B Q4_K_M | Q4_K, Q6_K | max diff 0 | France 16, Fibonacci 32: exact |
| Qwen3-1.7B Q2_K | Q2_K, Q3_K, Q6_K | max diff 0 | France 16, Fibonacci 32: exact |

## Decode measurements

Measured on the local Apple Metal device, short prompts, with shader compile
included in first prefill but excluded from decoded tokens:

| Model | DSM Metal decode tokens/s | llama.cpp comparison |
| --- | ---: | --- |
| Q8_0 | 30.37 - 33.46 | use `llama-simple` stderr; `llama-bench` is not built |
| Q4_K_M | 6.08 - 6.18 | use `llama-simple` stderr |
| Q2_K | 12.86 - 13.41 | use `llama-simple` stderr |

The first correct K kernels favor transparent byte-wise unpacking over speed.
They use one 256-thread group per output row and are the next optimization
target.
